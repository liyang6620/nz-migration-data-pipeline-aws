# Contributing

Thank you for taking the time to improve this project.

## Before opening a change

- Open an issue for substantial changes so the scope and approach can be agreed first.
- Do not include credentials, personal data, proprietary material, or unlicensed datasets.
- Preserve source attribution and document any new external data or media.

## Development workflow

1. Fork the repository and create a focused branch from main.
2. Follow the setup instructions in the README.
3. Keep changes small and include tests or validation evidence where applicable.
4. Run the checks defined in .github/workflows/ci.yml locally when practical.
5. Open a pull request using the repository template.

## Pull requests

A pull request should explain the problem, the chosen approach, validation performed, and any deployment or data implications. User-facing changes should include before-and-after evidence when relevant.

By contributing, you agree that your contribution is licensed under this repository's license.
